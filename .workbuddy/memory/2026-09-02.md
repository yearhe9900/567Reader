## 点击底部导航栏跨页跳（0↔2）「卡在发现页」——根因【已修正】
- 现象：点导航从书架(0)→设置(2)、设置(2)→书架(0) 停在中间的发现页(1)；相邻切换(0↔1、1↔2)正常。
- ❌ **先前误判**：以为是 `animateScrollToPage` 默认 spring 位移 2 倍页宽、收尾慢、逐帧渲染中间页导致"卡"。据此做的「跨页瞬跳 `scrollToPage`」只是**绕行方案，未触及根因**。
- ✅ **真正根因 = 同一个导航栏回环**（见下条）。完整链路：
  1. 点击设置(2) → `selectedTab = 2` → `animateScrollToPage(2)` 启动
  2. 动画滚过中点，`currentPage` 变为 1
  3. `LiquidBottomTabs` 的 `snapshotFlow { currentIndex }` 触发 → `onTabSelected(1)`
  4. 此时 `selectedTabIndex()` 已是 2，`1 != 2` → 走 else → **`selectedTab = 1`**
  5. `LaunchedEffect(selectedTabIndex())` 的 key 由 2 变 1 → **旧动画被取消** → `animateScrollToPage(1)`
  6. 页面**真的停在发现页**，不是慢
- **这同时解释了"相邻切换正常"**：相邻时回环回调的 index 与 selectedTab 相同，`handleTabClick` 走双击分支、不改 selectedTab，动画不被打断。
- **最终方案（跨页观感定稿）**：相邻页 = `animateScrollToPage` 短促 tween 200ms；
  跨页 = `scrollToPage` 瞬跳 + 整页淡入（`pageFade` Animatable，snapTo 0.35 → animateTo 1f，160ms）。
  - 中间曾试过「跨页统一 tween 280ms」，用户反馈**快速掠过发现页观感不好**，遂改回瞬跳。
  - 瞬跳在此**不是 workaround，而是观感选择**：HorizontalPager 0→2 必然经过发现页，用户不希望看到。
  - 淡入起点取 0.35f 而非 0：淡入期间始终能看到内容轮廓，不会闪出底层背景色。
  - `graphicsLayer { alpha = pageFade.value }` 加在 HorizontalPager 上；底部导航栏不在 pager 内，不受影响。
  - 去掉淡入（完全无过渡）：删掉 `pageFade.snapTo` / `pageFade.animateTo` 两行即可。
- import：`androidx.compose.animation.core.FastOutLinearInEasing`、`androidx.compose.animation.core.tween`、`kotlin.math.abs`。
- 经验：Compose Pager 的 `settledPage` 在动画期间保持旧值、settle 后才更新；`LaunchedEffect` 的 key 一旦变化就会**取消旧协程**，正在跑的 `animateScrollToPage` 会立刻中断——排查"动画被莫名打断"时优先查 key 是否被回环改写。

## 左右滑动翻页丢帧——根因与修复
三个叠加原因，按影响排序：

1. **程序化滚动与用户手势打架（最主要）**
   - 导航栏 `selectedTabIndex = { pagerState.currentPage }`，滑动过中点时 currentPage 变化 → `snapshotFlow → currentIndex → onTabSelected(index)` → MainActivity `selectedTab` 变化 → `LaunchedEffect(selectedTabIndex())` 触发 `animateScrollToPage`，在手势中途抢走滚动控制权。
   - 修复：`val isUserDragging by pagerState.interactionSource.collectIsDraggedAsState()`，`LaunchedEffect` 开头 `if (isUserDragging) return@LaunchedEffect`。
   - import：`androidx.compose.foundation.interaction.collectIsDraggedAsState`。

2. **底部玻璃导航栏 3 层 drawBackdrop 的 GPU 后处理**
   - `LiquidBottomTabs` 共 3 层，每层 `vibrancy() + blur(8dp) + lens()`，滑动时逐帧重算。
   - 修复：`LiquidBottomTabs` 新增 `glassEffectsEnabled: () -> Boolean` 参数；三处 `effects { }` 用 `if (glassEffects) { ... }` 包裹。
   - `MainScreen` 传 `glassEffectsEnabled = { !pagerState.isScrollInProgress }`。

3. **导航栏滑块 spring 动画拖长重绘窗口**
   - `DampedDragAnimation.animateToValue` 用 `spring(1f, 1000f, 0.001f)`，pager 滑动结束后仍跑数百毫秒，每帧改 `value` → 导航栏逐帧重绘。
   - 修复：`DampedDragAnimation` 新增 `val isAnimating get() = valueAnimation.isRunning || velocityAnimation.isRunning`（`Animatable.isRunning` 本身是 snapshot state，无需额外标志位）。
   - `LiquidBottomTabs` 内 `val glassEffects by remember { derivedStateOf { glassEffectsEnabled() && !dampedDragAnimation.isAnimating } }`。

**性能写法要点**：
- 参数用 `() -> Boolean` 而非 `Boolean`，把 state 读取限制在子组件内部，避免拖累 MainScreen 整屏重组。
- `derivedStateOf` 包一层，使 true/false 只在切换瞬间通知；读取发生在 `effects`/`highlight` 等 **draw 阶段** lambda 中 → 只 invalidate draw、不触发 composition 重组。
- 玻璃特效开关视觉几乎无损：backdrop 采样源是纯色渐变，blur/lens 对它的输出几乎不变。

## 【核心】滑动「段落感」= 导航栏 ↔ pager 的 selectedTab 回环
- 用户澄清「不是丢帧，而是有段落感」→ 即滚动被中断/接管，而非帧率不足。
- **回环链路**（6 步）：
  1. 用户滑动 pager，`pagerState.currentPage` 过中点变化（0→1）
  2. `LiquidBottomTabs` 的 `LaunchedEffect(selectedTabIndex)` 中 `snapshotFlow { selectedTabIndex() }` → `currentIndex = 1`
  3. `LaunchedEffect(dampedDragAnimation)` 中 `snapshotFlow { currentIndex }.drop(1)` 触发 → `animateToValue(1f)` **+ `onTabSelected(1)`**
  4. `onTabSelected` = MainScreen 的 `handleTabClick(1)`
  5. 此时 `settledPage` 仍为 0 → 走 else 分支 → MainActivity `selectedTab = 1`
  6. `LaunchedEffect(selectedTabIndex())` 触发 → `animateScrollToPage(1)`，**在手势/fling 中途抢走滚动控制权** → 段落感
- 上一轮加的 `isUserDragging`（`collectIsDraggedAsState`）**挡不住**：它只在手指按住时为 true，松手进入 fling 后立刻变 false，第 6 步照常执行。只能作为兜底，不能作为主手段。
- **根本修复**：切断回环。`LiquidBottomTabs` 里 `onTabSelected` 只保留两条真实用户交互路径：
  - tab 点击 → `LiquidBottomTab(onClick = { handleTabClick(item.position) })`（本就不经过 flow）
  - 拖动导航栏 → `onDragStopped` 里显式 `onTabSelected(targetIndex)`
  - `LaunchedEffect(dampedDragAnimation)` 的 flow 里**只保留 `animateToValue()`，删掉 `onTabSelected(index)`**（滑块仍跟手移动，但不再反向驱动 pager）
- 切断后 pager 滑动时 `selectedTab` 只在 `settledPage` 变化时（滑动完全结束）更新，此时 `settledPage == target` 直接 return，不会再有程序化滚动。
- **通用教训**：`ViewPager/Pager` + 底部导航双向同步时，必须保证「外部同步进来的状态变化」不再反向回调出去，否则一定打架。判断依据应是「变化来源」而非「是否正在滚动」。

## 【次要，未处理】导航栏滑块不跟随 pager 连续滑动
- 滑块位置由 `dampedDragAnimation.value` 驱动，只在 `currentIndex` 变化时（过中点）用 `spring(1f, 1000f, 0.001f)` 动画跳过去，不跟随手指连续移动。
- 若用户反馈的「段落感」指的是滑块而非页面，需把连续位置 `pagerState.currentPage + currentPageOffsetFraction` 传给导航栏驱动滑块。改动涉及 DampedDragAnimation 的值驱动方式（需 snapTo 而非 animateTo，否则每帧 launch 协程），风险与收益待评估。

## 【待决策】MainScreen 的 glass backdrop 源实际失效
- 结构：`Box(渐变).layerBackdrop(backdrop)` 在下，`Box(fillMaxSize).background(bgColor)` 不透明层在上**完全覆盖**它，再上面才是 HorizontalPager。
