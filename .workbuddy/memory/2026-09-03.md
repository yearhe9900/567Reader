## 抽出玻璃弹框视觉令牌 GlassDialogTokens
- 用户问题：项目是否有常量类？要求把 dialog 相关参数做成常量，并让其他玻璃态弹框复用。
- 结论：常量类 `constant/AppConst.kt`（`object AppConst`）存在，但放的是 App 级常量（channel/fileProvider/签名/时间格式），UI 玻璃令牌混进去不合适 → 新建专门的 `ui/compose/glass/GlassDialogTokens.kt`。
- 新增 `GlassDialogTokens` object：集中深色固定配色 `contentColor=White`/`accentColor=#0091FF`/`containerColor=#121212·0.4`/`dimColor=#121212·0.56`/`scrimColor=Black·0.5`；以及 `scrim`/`card`/`widget` 三档的 `blur`/`lens`(Dp) 与 `brightness`/`saturation`(Float) 常量。
- 新增 `glassDialogColors(isEInkMode)` 解析器：`data class GlassDialogColors` 按 E-Ink 回退黑白高对比（containerColor=White、dim/scrim=Transparent）。
- 复用改造（三处生产弹框全部改为引用令牌，消除同一套数值硬编码三遍）：
  - `GlassAlertDialog.kt`（书籍信息页删除书籍弹框）：颜色走 `glassDialogColors(isEInkMode)`，effects 用 `GlassDialogTokens.*`。
  - `ExplorePage.kt` 删除书源框：原本硬编码深色值且无 E-Ink 处理 → 现统一走令牌并补全 `if(!isEInkMode)` 跳过 glass。
  - `MySettingsScreen.kt` `ThemeModeDialogOverlay`：同上。
- 未动（性质不同，仅记录）：`LiquidDialog.kt`（仅 GlassDemoActivity 用，按 isSystemInDarkTheme 明暗分支，深色分支值恰等于令牌）、`LiquidBottomTabs.kt`（底部导航栏，按明暗主题切换）、`GlassDialog.kt`/`GlassCard.kt`（已无调用点，疑似死代码）。
- 提交 `88e0e08` refactor(dialog): 抽出玻璃弹框视觉令牌 GlassDialogTokens 供三处复用。
- 经验：kyant `drawBackdrop` 的 `effects{}` 内 `blur(x.dp.toPx())` 的 `.toPx()` 依赖 DrawScope/Density 隐式接收者；把 dp 值提为常量后，调用处仍需 `.toPx()`，常量只存 Dp，不可直接存 px。

## 修复：书架玻璃标题栏 registerMenuAction 类型括号不匹配 + 行尾告警
- 前序提交 `a2c00a3`（feat: 玻璃标题栏恢复搜索与更多菜单）未跑构建，用户 build 报 `Function 'BookshelfPage'/'MainScreen' must have a body` 级联报错。
- 根因：`BookshelfPage.kt`/`MainScreen.kt` 的 `registerMenuAction` 参数类型写成 `((BookshelfMenuAction) -> Unit)?) -> Unit`（2 开 3 闭），多余 `)` 提前闭合函数参数列表。修正为 `(((BookshelfMenuAction) -> Unit)?) -> Unit`（3 开 3 闭），与 `registerGotoTop: ((() -> Unit)?) -> Unit` 同形。
- 删除 `BookshelfTopBar` 时漏删其残留导入，产生 unused-import 警告，已清理：BookshelfPage 移除 `background`/`height`/`painterResource`/`SearchActivity`；MainScreen 移除 `WindowInsets`/`statusBars`/`windowInsetsPadding`/`LiquidGlassStyle`。（`getValue`/`setValue` 因 `by` 委托需要，非 unused。）
- LF/CRLF 行尾警告：工具以 LF 写文件，仓库 Windows+autocrlf 用 CRLF，每次 git 触碰报 "LF will be replaced by CRLF"。新增 `.gitattributes`：`* text=auto eol=crlf`，脚本 `*.sh`/`gradlew` 保留 `eol=lf`；并把被工具改写的 .kt 与 .gitattributes 本身 renormalize 为 CRLF。
- 提交 `1389560` fix(bookshelf)（编译修复+清理导入）、`e6eb730` chore(.gitattributes)。
- 经验：Kotlin 注册函数类型 `((X)?) -> Unit` 易漏括号；改完 .kt 后务必 `./gradlew :app:assembleAppDebug` 验证（命令由用户手跑，agent 不跑 build/adb）。

## 修复：handleMenuAction 前向引用 Unresolved reference
- 用户 rebuild 报 `BookshelfPage.kt:223:30 Unresolved reference 'handleMenuAction'`（Function-must-have-body 级联已消失，说明括号修复生效）。

- 修复：把 `handleMenuAction` 整段上移到 `DisposableEffect` 之前（其引用的 `activity`/`books`/`groupId`/`showAddUrlDialog`/`exportFileLauncher` 等状态均在函数体前部 `val` 声明，安全）。提交 `bdbf1a6`。
- 行尾复发：每次用 Edit/Write 工具改文件都会写 LF，git 又报 "LF will be replaced by CRLF"。已养成流程——改完并提交后 `git checkout -- <file>` 把工作区 renormalize 回 CRLF，使 `git status` 干净无告警。
