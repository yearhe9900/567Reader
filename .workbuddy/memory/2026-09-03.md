## 根因定位 + 结论：封面为空是「运行期在 Tab 样式」
- logcat 证据：每条 LaunchedEffect 日志 `bookGroupStyle=0`（非 Folder=1），且**全程无** `precompute result:` 日志 → 预计算 `if (bookGroupStyle == 1 && groupId == BookGroup.IdRoot)` 整段被跳过，`groupCoverBooks` 恒为空 map，4 格全 `invisible()`。
- 分组数据本身正常：`bookGroups observer fired size=4 ids=[-1,-2,1,2]`。
- 关键事实：**分组文件夹宫格只在 Folder 样式(`bookGroupStyle==1`)下渲染**。Tab 样式下 `LaunchedEffect(bookGroups, bookGroupStyle)` 会把 `groupId` 自动设为某个真实分组(如 -1)，`currentItems` 不加入 `bookGroups`，根页不显示分组卡片，封面预计算无意义。`AppConfig.bookGroupStyle` 默认值就是 `0`(Tab)，所以开箱即 Tab。
- 用户决策：**切到文件夹样式即可，封面逻辑无需改**（代码在 Folder 样式下已正确）。
- 清理：删除 BookshelfPage / BaseBooksAdapter 的临时 Log.d 诊断日志；修正 BaseBooksAdapter 注释过时 `3×3`→`2×2`。提交 `d4effaa`。
- 用户侧操作：书架设置把「分组样式」改为「文件夹」后重跑即可见封面；adb logcat 在 Windows 无 `grep`，用 PowerShell `Select-String "BookshelfPage|BaseBooksAdapter"` 或 `findstr`。
- 闪屏（进入分组时 groupId 在 -100/-1/-2/1/2 跳变、itemCount 4→15→4）仍待处理，且 Tab 样式时序问题在进入 Folder 样式后行为会变，封面验证后再看。
