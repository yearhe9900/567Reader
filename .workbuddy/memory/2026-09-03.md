## 根因定位 + 结论：封面为空是「运行期在 Tab 样式」
- logcat 证据：每条 LaunchedEffect 日志 `bookGroupStyle=0`（非 Folder=1），且**全程无** `precompute result:` 日志 → 预计算 `if (bookGroupStyle == 1 && groupId == BookGroup.IdRoot)` 整段被跳过，`groupCoverBooks` 恒为空 map，4 格全 `invisible()`。
- 分组数据本身正常：`bookGroups observer fired size=4 ids=[-1,-2,1,2]`。
- 关键事实：**分组文件夹宫格只在 Folder 样式(`bookGroupStyle==1`)下渲染**。Tab 样式下 `LaunchedEffect(bookGroups, bookGroupStyle)` 会把 `groupId` 自动设为某个真实分组(如 -1)，`currentItems` 不加入 `bookGroups`，根页不显示分组卡片，封面预计算无意义。`AppConfig.bookGroupStyle` 默认值就是 `0`(Tab)，所以开箱即 Tab。
- 用户决策：**切到文件夹样式即可，封面逻辑无需改**（代码在 Folder 样式下已正确）。
- 清理：删除 BookshelfPage / BaseBooksAdapter 的临时 Log.d 诊断日志；修正 BaseBooksAdapter 注释过时 `3×3`→`2×2`。提交 `d4effaa`。
- 用户侧操作：书架设置把「分组样式」改为「文件夹」后重跑即可见封面；adb logcat 在 Windows 无 `grep`，用 PowerShell `Select-String "BookshelfPage|BaseBooksAdapter"` 或 `findstr`。
- 闪屏（进入分组时 groupId 在 -100/-1/-2/1/2 跳变、itemCount 4→15→4）仍待处理，且 Tab 样式时序问题在进入 Folder 样式后行为会变，封面验证后再看。

## 修正：编辑分组蒙板「还是不全屏」—— 真根因是 AnimatedVisibility 嵌套在底部导航栏小 Box 里
- 上一节（52cc027）给 `AnimatedVisibility` 加 `Modifier.fillMaxSize()` 并未解决，用户 rebuild 后仍报「蒙板不全屏」。原记录把根因写成 AnimatedVisibility 的 `wrapContentSize` 是错的。
- **真根因**：`MainScreen.kt` 中包 `GroupEditOverlay` 的那个 `AnimatedVisibility` 被写在了**底部导航栏 `Box`（`align(Alignment.BottomCenter).fillMaxWidth()` + 只有内容高）的内部**，是其子节点。所以 `fillMaxSize()` 撑满的只是这个「底部小条」Box，scrim `Box(fillMaxSize)` 实际只覆盖底部一小块 —— 根本不是 wrapContentSize 的问题。
- **修复**：把该 `AnimatedVisibility` 从底部导航栏 Box 里移出，提升为**全屏外层 `Box(Modifier.fillMaxSize())`（line 236）的直接子节点**（与 backdrop 捕获 Box / 标题栏 / 底部导航栏平级，且最后一个子节点 → 画在最上层）。
- 已复查另外两处 `LiquidGlassDialog` 调用：`MySettingsScreen.ThemeModeDialogOverlay` 的 `AnimatedVisibility` 已是全屏根 `Box(Modifier.fillMaxSize())` 的直接子节点（无此 bug）；`GlassAlertDialog` 自有 `Box(Modifier.fillMaxSize())` 根 → 蒙板天然全屏。仅编辑分组这一处踩坑。
- 同步修正 `LiquidGlassDialog.kt` KDoc：把「AnimatedVisibility 须加 fillMaxSize」改为准确表述——「其外层容器必须撑满全屏；不要把 AnimatedVisibility 嵌套进 align/fillMaxWidth 的小 Box（如底部导航栏），否则 fillMaxSize 至多填满该小 Box」。
- 一句话经验：Compose 里「蒙板不全屏」先查**外层容器是不是全屏、弹框是不是被塞进了某个 anchor/小 Box**，再怀疑 wrapContentSize。`AnimatedVisibility` 的 `fillMaxSize` 只在它「父容器本身全屏」时才真正生效。
