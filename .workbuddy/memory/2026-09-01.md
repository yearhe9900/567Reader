## MPP → Android Compose 移植 API 陷阱（重要）
- 工程 Compose 为 **BOM 2025.08.00 = Compose 1.12.0**（新版本）。
- 官方 AndroidLiquidGlass 是 **Compose Multiplatform (commonMain)** 工程，其 `DampedDragAnimation.kt` 用顶层 `awaitFrame()`（无 import）。该符号 **以及** `androidx.compose.ui.graphics.withFrameNanos`、`androidx.compose.ui.graphics.MonotonicFrameClock` 在 **Android-only Compose 1.12 的 `androidx.compose.ui.graphics` 顶层均解析不到**（帧时钟顶层 API 已被移走；同包 `Color` 等仍能解析，说明只是帧时钟类被挪走，非 ui-graphics 缺失）。
- **最终可用修复**：`DampedDragAnimation` 内实现私有 `suspend fun awaitFrame() { yield() }`，`import kotlinx.coroutines.yield`。`yield()` 让出协程槽等价于等一帧机会；真正等待动画落位由后面的 `snapshotFlow{value}.filter{}.first()` 在帧上收集完成。规避所有 Compose 帧 API 版本差异。
- 经验：移植 Compose Multiplatform catalog 代码到 Android 1.12 时，帧同步/动画时钟的 MPP 顶层函数（`awaitFrame`/`withFrameNanos`/`MonotonicFrameClock`）不能直接搬，用 `kotlinx.coroutines.yield()` 兜底最稳。
- 注：本地 Gradle 缓存（`~/.gradle/caches`）仅含 `.module`/`.pom` 元数据，无实际 AAR，无法反查符号，遇到 API 差异需靠版本无关写法兜底。

## 启动黑屏回归修复（「我的」Compose 页离屏渲染）
- 现象：启动停在欢迎页 → 黑屏（用户确认触发时机为「启动后停在欢迎页→黑屏」）。
- 根因：MainActivity 用 ViewPager + `offscreenPageLimit=3`，启动时会预加载全部 3 个 tab（含 MyFragment）。MyFragment 在 `onFragmentCreated` 立即 `setContent` 渲染 MySettingsScreen，其 Liquid Glass backdrop（`rememberLayerBackdrop` + `drawBackdrop`，底层是 `GraphicsLayer` + AGSL RuntimeShader blur，GPU 密集）在**离屏/启动早期**被渲染，触发 Surface 渲染异常 → 黑屏。
- 修复：MyFragment 改为**懒加载**——把 `setContent` 从 `onFragmentCreated` 移到 `onResume`（`FragmentStatePagerAdapter` + `BEHAVIOR_RESUME_ONLY_CURRENT_FRAGMENT` 保证离屏 fragment 不 resume，只有切到「我的」时才渲染）。用 `composeInitialized` 标志防重复 setContent。
- 验证：需用户手动 `assembleDebug` 装机测试。若切到「我的」仍黑屏，则需降级玻璃效果（移除 drawBackdrop 改普通 background）。

## 修复「我的」页 ClassCastException（themeMode 类型不匹配）
- 现象：启动即崩溃 `ClassCastException: String cannot be cast to Integer`，栈指向 `MyFragment.onFragmentCreated:58` 的 `getPrefInt(PreferKey.themeMode, 0)`。
- 根因：`PreferKey.themeMode` 全项目统一按**字符串**存取（AppConfig.kt 用 getPrefString/putPrefString，值 "0"跟随系统 /"1"亮色/"2"暗色/"3"墨水屏，theme_mode_v 数组）。而新写的 MyFragment 误用 getPrefInt/putPrefInt 读写同一 key，触发 SharedPreferences 强转崩溃。
- 修复：MyFragment 改 `getPrefString(PreferKey.themeMode, "0")?.toIntOrNull() ?: 0` 读取、`putPrefString(PreferKey.themeMode, value.toString())` 写入，并同步 import 换为 getPrefString/putPrefString。themeModeIndex 语义 = 0..3 数组下标，与 R.array.theme_mode 对应。
- 教训：PreferKey 里不同 key 的类型约定必须按 AppConfig.kt 的既有读法对齐，不能想当然 getPrefInt。

## 修复主题模式弹框导致页面下移
- 现象：ThemeModeDialog（Compose Dialog）弹出后，底层 Activity 页面整体下移几个像素。

## 主题模式弹框改用 Popup，彻底解决页面下移/闪动
- 现象：用户反馈 `setDecorFitsSystemWindows` 修复后，顶部仍出现占位，页面整体下降并闪动。
- 根因：`SideEffect` 在 Dialog 窗口首次布局后才执行，系统已有过一轮 insets 计算与重布局，导致视觉上先下移再复位，产生闪动；部分设备/系统栏场景下 `setDecorFitsSystemWindows` 也不足以阻止父 Activity 被重新 fit。
- 修复：将 `ThemeModeDialog` 从 `androidx.compose.ui.window.Dialog` 改为 `androidx.compose.ui.window.Popup`。
  - Popup 在当前 Window 内部绘制，不创建新 Window，不会触发父 Activity 的 insets 重布局，从根源避免下移与闪动。
  - 设置 `PopupProperties(focusable = true, dismissOnBackPress = true, dismissOnClickOutside = false)`，保持返回键关闭与外部点击关闭行为。
  - 内容区保持原有玻璃态结构：全屏 clickable Box（点遮罩 dismiss）+ 居中 `drawBackdrop` 卡片 + 单选列表 + 取消/确定胶囊按钮。
- 代码改动：`MySettingsScreen.kt`：
  - import 移除 `Dialog`/`DialogProperties`/`WindowCompat`/`SideEffect`；新增 `Popup`/`PopupProperties`。
  - `ThemeModeDialog` 函数体用 `Popup(...)` 替换 `Dialog(...)`，删除内部 `SideEffect` 窗口配置。
- 保留：页面截图采样 `capturePageSnapshot()` 与 `themeDialogBackdrop` 仍作为玻璃 backdrop 采样源（Popup 弹出前截图，因此不包含 Popup 自身）。

## Popup 二次修正：focusable=false + BackHandler
- 现象：上述 Popup(focusable=true) 方案装机测试后仍出现顶部占位 + 页面下移 + 闪动。
- 根因（关键）：Compose `Popup` 在 `focusable=true` 时底层走的是 `Dialog` 实现（创建子 Window），并不是真正的 PopupWindow！所以仍然会触发父 Activity 的 insets 重布局，前一轮"Popup 不创建新 Window"的说法有误。
- 最终修复：
  - `PopupProperties(focusable = false, dismissOnBackPress = false, dismissOnClickOutside = false)`：强制走 `PopupWindow` 子视图路径，完全不创建新 Window，彻底不触发 insets 重布局。
  - 返回键：用 `androidx.activity.compose.BackHandler { onDismiss() }` 在 Popup 内容里拦截（依赖 activity-compose 1.11.0，已在 libs.versions.toml）。
  - 外部点击：保留全屏 `Box(clickable=onDismiss)`。
- 代码改动 `MySettingsScreen.kt`：
  - 新增 `import androidx.activity.compose.BackHandler`。
  - `ThemeModeDialog` 内 Popup 改为 `focusable=false`、在 Popup 内容首行加 `BackHandler { onDismiss() }`。
- 教训：Compose Popup 的 `focusable` 决定底层走 Dialog 还是 PopupWindow，需要"不创建新 Window"必须显式 `focusable=false`，并自行用 BackHandler 处理返回键。

## 主题模式弹框最终方案：DialogFragment（与删除图书弹框同一机制）
- 用户关键观察：删除图书弹框（GlassAlertDialog，DialogFragment + `Theme_Translucent_NoTitleBar`）只改变系统状态栏/手势栏颜色，**不扰动 Activity 布局**；而主题弹框（Compose Dialog/Popup）会让底层「我的」页标题栏颜色+高度变化、整体下移闪动。

## 编译错误修复：flavor 任务名 + weight import（整页迁移 Compose 收尾）
- 任务名歧义：`app` 模块有 product flavor `app`（`flavorDimensions=['mode']`），所有变体任务带 `App` 前缀。正确命令 `:app:compileAppDebugKotlin` / `:app:assembleAppDebug`（不是 `compileDebugKotlin`/`assembleDebug`，后者报 `Ambiguous matches`，候选含 AndroidTest/UnitTest 变体）。APK 输出 `app/build/outputs/apk/app/debug/567Reader.apk`。
- 编译错误：`MainScreen.kt` 报 `Cannot access 'val RowColumnParentData?.weight: Float': it is internal in file`，指向 `import androidx.compose.foundation.layout.weight`。
- 根因：Compose 1.12（BOM 2025.08.00）中 `Modifier.weight()` 是 `RowScope`/`ColumnScope` 的**接口成员函数**（作用域内直接可用，无需 import）；顶层 `weight` 符号会解析到 internal 的 `RowColumnParentData?.weight` 属性。
- 修复：删除 `import androidx.compose.foundation.layout.weight`。两处 `.weight(1f)`（AndroidView 在 Column 内、EInkBottomBar 的 Column 在 Row 内）均在作用域内，删除 import 后正常解析。
- 教训：Compose 1.12 的 `weight` 不能 import，与 `padding`/`fillMaxWidth` 等顶层 Modifier 扩展不同（后者是顶层函数可 import）。

## 主题弹框「不加截图」的后果（设计取舍，防误删截图）
- 玻璃链路：`MyFragment.decorView.draw(Canvas)` → `backdropBitmap` → `Image(backdropPainter).layerBackdrop(backdrop)` → `Column().drawBackdrop(backdrop=...)`。
- `layerBackdrop` 只能捕获**同一 composable 树内**内容，**跨不过 DialogFragment 的独立 Window 边界**去采 Activity 那页。截图即"跨窗口桥"，把真实页面像素喂给玻璃。
- 不加截图三选一：①连 Image 整层删 → backdrop 空白 → 玻璃只剩 containerColor 的 flat 卡片，无磨砂；②只留 `SolidColorPainter(pageBackgroundColor)` 兜底 → 玻璃采纯色填充 → 均匀着色卡片，仍非"页面磨砂"；③要真实磨砂又不截图 → 须回同窗口 overlay(Compose Dialog/Popup 共享 layerBackdrop)，但重触发顶部占位/下移/闪动（已修过的坑）。
- 结论：截图是 DialogFragment 方案的必要代价，换「不扰动 Activity 布局 + 玻璃仍反映真实页面」。官方 `LiquidDialog` 不截图是因同窗口调用方传 live `Backdrop`。勿把截图当冗余优化删掉。

## 闪退修复：Activity 字段初始化阶段禁止访问 SharedPreferences
- 现象：装上新包后启动 app 即闪退。
- 根因：`MainActivity` 里 `private var glassConfig by mutableStateOf(NavBarGlassConfig.load(this))` 是**字段初始化器**，在 Activity `attach()` **之前**执行（ActivityThread 流程是 `newInstance()` 触发构造/字段初始化 → 之后才 `activity.attach(...)`）。此时 `ContextWrapper.mBase` 仍为 null，`getPrefString → PreferenceManager.getDefaultSharedPreferences(this) → getSharedPreferences` 触发 `mBase.getSharedPreferences(...)` NPE。

- 教训：Activity/Fragment 的**字段初始化器**里绝不能碰 `context`（SharedPreferences、getString、resources 等），要延迟到 `onCreate/onActivityCreated/onViewCreated` 或 `by lazy` 延迟访问。此坑与 `by lazy { TabFragmentPageAdapter(supportFragmentManager) }` 形成对照——lazy 延迟到 initView 才访问，故不崩。
